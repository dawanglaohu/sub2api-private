# 14 测试与验证策略

## 分层验证

| 层级 | 主要命令或证据 | 重点 |
|---|---|---|
| Go 单元/集成 | `cd backend && go test ./...` 或按 package 定向运行 | service 状态机、repository、middleware、协议适配、并发与补偿 |
| 前端单元 | `cd frontend && pnpm test --run <files>` | router guard、store、API client、组件与聚蚁注入 |
| 前端构建 | `cd frontend && pnpm install --frozen-lockfile && pnpm run build` | vue-tsc、Vite、import 冲突、嵌入资源 |
| Compose/脚本 | `deploy/tests/` 与配置静态核对 | 环境变量、PGDATA、资源限制、Caddy/安装脚本 |
| 镜像 smoke | `update-from-ghcr.sh smoke custom-<sha8>` | `/health`、版本、聚蚁 logo、临时数据库迁移 |
| 生产验收 | 内部 8181 + 公网浏览器 + 容器日志 | 品牌页面、设置、真实链路、console 和 rollback 位 |

## 变更到测试的映射

- M1/M2：配置、Wire、迁移、repository package tests；启动/关闭路径需进程级验证。
- M3：auth route、JWT/API key middleware、OAuth pending flow、身份并发测试。
- M4/M5：gateway handler、scheduler、provider adapter、流式和 cancellation tests。
- M6：usage billing、payment lifecycle、webhook、fulfillment、refund transaction tests。
- M7：queue、worker runtime、billing recovery、idempotency 和 storage ownership tests。
- M8/M9：Ops aggregation、Prompt Audit modes、plugin package/runtime/reconcile tests。
- M10/M11/M12：router/store/API/component tests，加 `pnpm run build` 防止 template/import 漏错。
- M13：Git ancestry、tag/version、manifest digest、隔离 smoke、备份 gzip、容器健康和公网验收。

## 发布硬门

1. 最新 release tag 必须是 custom 祖先，净差异只能是聚蚁清单。
2. 前端 build 必过；后端按变更范围至少完成编译和定向测试。
3. 只部署 `custom-<sha8>`，确认版本别名与不可变标签指向同一 manifest。
4. smoke 不挂生产卷，且健康、版本、品牌 marker 全过。
5. switch 前产生新备份并做完整性校验。
6. switch 后检查内部与公网健康、设置、容器、日志和浏览器 console。
7. smoke 栈在验证后 `smoke-down`，避免长期占资源。

## 本次知识库验证口径

知识库自身的验证包括：GitHub release 同步事实、源表可解析、所有边界有任务兜底、代码链接不产生幽灵节点、受保护块重跑不丢失、`build_vault.py --check` 通过，以及 `check_coverage.py --check` 将全部 tracked files 分配给已定义模块。覆盖检查不能替代业务 build/test；业务代码变化仍按上表运行对应测试。
