# 08 接口约定

## 接口分区

| 分区 | 典型路径 | 认证 | 责任 |
|---|---|---|---|
| 通用 | `/health` | 无 | 健康检查与运行状态 |
| 面板 API | `/api/v1/auth`、`/api/v1/admin`、`/api/v1/payment` | JWT/admin/step-up，按路由组合 | 用户、管理员、支付与设置管理 |
| Claude/OpenAI 兼容网关 | `/v1/messages`、`/v1/responses`、`/chat/completions` | API Key | 协议归一、调度和上游转发 |
| Gemini 原生兼容 | `/v1beta/models/*` | API Key，兼容 `x-goog-api-key` | Gemini SDK/CLI 接入 |
| Codex 兼容别名 | `/backend-api/codex/*` | API Key | Codex app/CLI 路径兼容 |
| 公共设置 | `/api/v1/settings/public` | 无 + IP 限流 | 站点名称、Logo、功能开关和自定义菜单 |
| Webhook | `/api/v1/payment/webhook/*` | provider 签名 | 支付状态通知与幂等履约 |

## API Key 约定

- 接受 `Authorization: Bearer`、`x-api-key`、`x-goog-api-key`。
- Query 参数 `key`/`api_key` 已废弃并直接返回 400；超长或无效凭据按统一模糊错误拒绝。
- Authentication 永远检查 Key、用户、组和 IP ACL；Billing Enforcement 可按端点跳过。
- `/v1/usage`、`/v1/sub2api/billing` 和异步图片任务查询允许额度耗尽的 Key 读取自身数据（E-08）。

## 协议与错误约定

- 能力门控在调度前执行，不支持的平台/子路径返回与入站协议一致的 404/错误体（E-13）。
- 流开始前的可重试上游错误可排除失败账号后 failover（E-14）。
- 流开始后不得切换账号并拼接第二条响应；只能按当前协议关闭或发流式错误（E-15）。
- 客户端取消必须向上游、等待队列和异步记录链路传播，不得继续占槽（E-16）。
- 每个请求使用 client request ID；Usage/Ops 记录保留协议、模型、用户、Key、账号、组和上游错误语义。

## 面板与设置约定

- 前端路由 guard 是体验层；后端 middleware/handler 保留最终授权。
- 公共设置暂时加载失败视为“未知”，前端不擅自判定功能关闭，后端继续 404/403 兜底（E-27）。
- 自定义菜单普通 URL 进入内部 `/custom/:id`；`ext:https://...` 才进入新窗口外链，后端只接受绝对 HTTP(S)（E-32）。
- 管理员高风险设置、支付与身份操作应经过 audit、compliance 或 step-up 组合（E-30）。

## 安全与日志

- 日志与 DTO 不输出 access token、refresh token、client secret、TOTP secret 或完整上游凭据。
- 验证失败信息不泄露 IP ACL 规则、Key 是否存在或身份绑定细节。
- 插件、Webhook、OAuth callback 与 Prompt Audit 的失败模式必须在对应边界笔记中明确是 fail-open、fail-closed 还是 degraded。
