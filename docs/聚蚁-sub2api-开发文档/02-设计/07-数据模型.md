# 07 数据模型

## 数据存储边界

PostgreSQL 是业务事实来源，Ent schema 定义实体和索引，`backend/migrations/` 承担跨版本演进。Redis 保存可重建的鉴权/调度缓存、限流、并发槽、队列、锁和短期会话；S3/本地存储承载图片输出、备份或插件包等大对象。缓存不可成为用户余额、订单或订阅状态的唯一事实来源。

## PaymentOrder 状态机

```mermaid
stateDiagram-v2
    [*] --> PENDING
    PENDING --> PAID: provider 已验签并确认
    PENDING --> CANCELLED: 用户取消
    PENDING --> EXPIRED: 超时关闭
    PENDING --> FAILED: 下单或核验失败
    CANCELLED --> PAID: 迟到但有效的支付通知（E-18）
    EXPIRED --> PAID: 迟到但有效的支付通知（E-18）
    PAID --> RECHARGING: 抢占履约 lease
    FAILED --> RECHARGING: 管理员重试履约
    RECHARGING --> COMPLETED: 余额或订阅入账
    RECHARGING --> FAILED: 履约失败
    COMPLETED --> REFUND_REQUESTED: 用户申请
    COMPLETED --> REFUNDING: 管理员退款
    REFUND_REQUESTED --> REFUNDING: 管理员受理
    REFUND_PENDING --> REFUNDING: 查询后继续
    REFUND_FAILED --> REFUNDING: 人工重试
    REFUNDING --> REFUND_PENDING: provider 异步处理中
    REFUNDING --> PARTIALLY_REFUNDED: 部分退款成功
    REFUNDING --> REFUNDED: 全额退款成功
    REFUNDING --> REFUND_FAILED: provider 或本地回滚失败（E-19）
    REFUNDING --> COMPLETED: provider 失败且本地扣减已回滚
```

## 不变量

- `UsageLog` 是计费、报表和 Ops 聚合共同依赖的事实记录；request ID 和主体外键必须可追踪。
- `PaymentOrder.out_trade_no` 只在非空时唯一，允许尚未拿到上游交易号的订单存在。
- Account 的管理状态、可调度状态、限流/过载窗口是不同维度，不能只看一个 `status` 字段决定调度。
- Batch Image 的幂等键与 manifest hash 防止重复提交；worker 状态和 billing hold 必须可恢复。
- Ent 生成代码不手改；变更从 schema 和 migration 开始，再重新生成并测试。
