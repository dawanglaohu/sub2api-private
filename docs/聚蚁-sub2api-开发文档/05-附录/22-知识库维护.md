# 22 知识库维护

## 目录职责

- 第 06 节模块表、第 11 节边界表、第 17 节任务表是图谱事实源。
- `图谱/模块/`、`图谱/任务/`、`图谱/边界/` 和 `_MOC.md` 由脚本派生。
- `_run/build_vault.py` 是本仓库固定生成器；不要用临时脚本重写派生笔记。
- `.obsidian/app.json` 只负责忽略 `_run/` 和设置附件目录，用户后续配置不会被生成器覆盖。

## 常用命令

```bash
python docs/聚蚁-sub2api-开发文档/_run/build_vault.py docs/聚蚁-sub2api-开发文档 --root .
python docs/聚蚁-sub2api-开发文档/_run/build_vault.py docs/聚蚁-sub2api-开发文档 --root . --check
python docs/聚蚁-sub2api-开发文档/_run/check_coverage.py --root . --check
```

在 Obsidian 中选择 `docs/聚蚁-sub2api-开发文档/`，执行 “Open folder as vault”。

## 回写规则

1. 笔记间只使用 Obsidian 双方括号链接。
2. 代码位置写成 `` `relative/path:line-range` — 说明 ``，不能写成 wikilink。
3. 只编辑 `<!-- code:begin -->`、`<!-- notes:begin -->` 等受保护标记之间的内容。
4. 不删除 marker；重跑会保留 marker 内原文并重建其余正文。
5. 实施沉淀记录代码看不出的约束、失败模式和取舍，不复述函数名。
6. 边界验证记录要写实际证据；未执行的测试明确写“建议回归”，不能冒充已通过。
7. 每次回写后重跑生成器，再执行 `--check`。

## 变更模块/任务/边界

- 新模块：先在第 06 节增加 `M<n>`，再给第 17 节增加至少一个所属任务。
- 新边界：先在第 11 节增加 `E-<nn>`，再在至少一个任务验收标准中引用该编号。
- 新任务：使用 `M<n>-T<n>`，依赖只能引用已存在任务，避免依赖环。
- 新增仓库目录或稳定业务域：同时更新第 21 节和 `check_coverage.py`；不能用过宽 fallback 让检查假通过。
- 删除节点前先查 backlinks 和代码回写；需要保留的历史取舍迁移到仍存在的任务沉淀。

## 术语

| 术语 | 含义 |
|---|---|
| Group | API Key 绑定的平台/计费/模型范围与账号池配置 |
| Account | 可被调度的上游账号或 API Key，携带凭据和运行态资格 |
| Sticky | session 到账号的偏好绑定；满载时不等于永久迁移绑定 |
| Composite | 可按模型解析到不同平台/账号组的组合路由 |
| Simple mode | 跳过 billing/quota enforcement 的简化运行模式，仍做基础鉴权 |
| Backend mode | 面板只允许管理员和有限公开路径的运行模式 |
| Mandatory usage | 不允许静默丢弃的用量记录路径 |
| Prompt Audit | 对入站/出站 prompt 扫描、策略决策和审计的子系统 |
| custom-SHA | 聚蚁 CI 产出的不可变生产镜像标签 |
