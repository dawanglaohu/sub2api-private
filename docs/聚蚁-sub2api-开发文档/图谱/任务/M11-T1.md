# M11-T1　维护用户控制台关键流程

- 所属模块：[[M11]]　用户与管理控制台：用户 Keys/Usage/Payment/Profile 和管理员 Accounts/Groups/Ops/Settings/Plugins
- 前置依赖：[[M10-T2]]、[[M5-T1]]、[[M6-T1]]、[[M7-T1]]、[[M14-T1]]、[[M14-T2]]
- 完成后解锁：[[M12-T1]]

## 输入 / 产出

- **输入**：用户 keys/usage/subscription/payment/task/运营数据
- **产出**：Dashboard、Keys、Usage、Payment、Profile 与站点运营页面

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) feature/mode/settings 不一致时提供可恢复路径（[[E-29]]）
2) 支付回跳只展示后端确认状态
3) 额度耗尽后仍可读自身 usage/task

## 必须处理的边界

- [[E-29]]　UI 功能开关、后端模式或支付恢复不一致
    - 触发：设置尚未加载、用户角色变化、支付回跳丢失页面状态
    - 期望：前端给出可恢复路径，后端最终授权；禁止展示成功但后端未履约

## 代码位置

<!-- code:begin -->
- `frontend/src/views/user/` — Dashboard、Keys、Usage、Payment、Profile 与任务页面
- `frontend/src/api/keys.ts` — API Key 用户接口
- `frontend/src/api/usage.ts` — 用量查询
- `frontend/src/api/payment.ts` — 下单、恢复和订单查询
- `frontend/src/components/payment/paymentFlow.ts` — 支付启动与结果编排（E-29）
<!-- code:end -->

## 实施沉淀

<!-- notes:begin -->
用户界面不自行推断履约成功，支付回跳和恢复都以服务端订单状态为准。Feature/mode 设置暂时未知时保留可恢复入口；后端拒绝后再显示原因，避免前端缓存把合法用户永久挡在外面。
<!-- notes:end -->
