# M2-T2　维护 repository、缓存与外部存储适配

- 所属模块：[[M2]]　数据模型与基础设施：Ent schema、PostgreSQL 迁移、repository、Redis/S3/外部 client adapters
- 前置依赖：[[M2-T1]]
- 完成后解锁：[[M3-T1]]、[[M4-T1]]、[[M6-T1]]、[[M8-T1]]、[[M9-T1]]、[[M13-T1]]、[[M14-T1]]、[[M14-T3]]、[[M15-T1]]

## 输入 / 产出

- **输入**：service ports、DB/Redis/S3 clients
- **产出**：可替换的数据与基础设施 adapters

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) PostgreSQL 保持事实权威
2) 缓存缺失/陈旧按策略回源或重建（[[E-04]]）
3) 密钥、锁、队列和连接失败可观测

## 必须处理的边界

- [[E-04]]　Redis 缓存缺失、陈旧或不可用
    - 触发：缓存过期、重启、网络抖动、outbox lag
    - 期望：只在明确配置的路径回源 DB 或重建；业务事实不由旧缓存覆盖，避免缓存击穿

## 代码位置

<!-- code:begin -->
- `backend/internal/repository/ent.go` — Ent client 和事务适配
- `backend/internal/repository/db_pool.go` — PostgreSQL 连接池
- `backend/internal/repository/redis.go` — Redis client 构造
- `backend/internal/repository/scheduler_cache.go` — 调度缓存 adapter（E-04）
- `backend/internal/repository/s3_client.go` — 对象存储 client
<!-- code:end -->

## 实施沉淀

<!-- notes:begin -->
Repository 隔离存储失败语义，service 不应依赖 Redis key 或 SQL 文案。缓存回源必须有 timeout、singleflight/QPS 或重建策略；直接把 Redis 错误当作“数据不存在”会覆盖真实身份、余额或调度状态。
<!-- notes:end -->
