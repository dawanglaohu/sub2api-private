## 输入 / 产出

- **输入**：request/error/latency/token 事件
- **产出**：聚合、趋势、实时流量、告警与监控结果

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 观测故障不无条件阻断网关（[[E-23]]）
2) 请求 ID 可从错误追到主体和上游
3) 聚合/清理任务有锁、窗口和降级记录

## 必须处理的边界

- [[E-23]]　Ops/监控链路不可用
    - 触发：聚合查询超时、日志 sink 或监控 runner 故障
    - 期望：网关主链路保持可用并记录降级；不得把观测故障误判成上游业务错误

## 实施沉淀

<!-- notes:begin -->
Ops/monitor 是主链路的旁路消费者，聚合或 UI 查询失败不应伪装成 AI 上游错误。必须保留 request ID、主体、平台和真实 upstream context；清理、聚合和告警任务使用锁/窗口避免多实例重复执行。

2026-08 V2 被动监控页重设计（用户四轮迭代确认）：移除筛选/状态栏，时间范围选择块（24h/3d/7d），按平台分组、每模型一张诊断卡，指标用 metric-chip 小方块（一格一指标、文字居中）。后端 ParseFilter 同步扩展：24h→5min、新增 3d→15min、7d 12h→1h，全部优先命中固定 rollup 表（3d 走 1m facts 重分箱）。

关键边界：① 非管理员响应会清零绝对请求数，活跃判定与色块着色必须用 buckets 存在性 + score，不能依赖 request_count；② 色带用 downsampleMonitorSlots 把全窗口均匀降采样为 60 块（比例切分、组大小差 ≤1），健康取组内最差（短时尖峰不丢），指标加权/等权合并，tooltip 显示合并后真实时间范围——任何范围都全窗口覆盖、无滚动；③ 查询失败只展示陈旧提示不误报模型状态；页面隐藏暂停轮询、重新可见立即刷新；新模型卡只淡入一次且尊重 reduced-motion；④ 平台身份色与语义状态色（绿/黄/红）分离，聚蚁主题令牌复用。

2026-08-31 修复边界色块明细被裁：卡片 `overflow-hidden`（色带必须被卡片裁住）会把绝对定位的明细窗一起裁掉，首尾色块只能看到半个窗。改为 `<Teleport to="body">` + `position: fixed`：activate 时用 `getBoundingClientRect` 取色块视口坐标，nextTick 量出窗尺寸后水平夹进视口（左右各留 8px）、上方空间不足（预留 84px 让开浮动 header）则翻到色带下方。fixed 是视口锚定的，滚动/缩放会脱锚，故窗打开期间监听 scroll(capture)/resize 直接关闭。副作用：明细窗不再在组件根内，单测要从 `document.body` 查询而非 `wrapper.find`。

矩阵 seed 的零流量行（request_count=0、无 buckets）被自然过滤；3d/7d 下旧流量模型（如 mock 的 zhipu）会因存在历史 buckets 而重新可见，这是预期行为。
