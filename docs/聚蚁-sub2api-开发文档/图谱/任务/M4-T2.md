# M4-T2　维护粘性、配额与并发感知调度

- 所属模块：[[M4]]　账号、分组与调度：账号凭据、平台分组、模型路由、sticky、并发、配额和可调度资格
- 前置依赖：[[M4-T1]]
- 完成后解锁：[[M5-T2]]、[[M7-T1]]

## 输入 / 产出

- **输入**：group、model、session、候选运行态
- **产出**：AccountSelectionResult 与等待计划

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) sticky 满载不改持久绑定并按规则临时处理（[[E-10]]）
2) cache/outbox 故障仅受限 DB fallback（[[E-11]]）
3) 配额/并发错误按 reset 冷却且保留 failover（[[E-12]]）

## 必须处理的边界

- [[E-10]]　Sticky 账号满载或失去资格
    - 触发：绑定账号容量溢出、停用、模型不支持或利润门禁失败
    - 期望：保持持久 sticky 绑定不被容量溢出迁移；本次请求按规则等待、临时 failover 或失败
- [[E-11]]　调度缓存或 outbox 落后
    - 触发：Redis 不可用、lag 超阈值、候选缓存不完整
    - 期望：在配置允许时受限回源 DB/全量重建；限制 QPS 和超时，避免雪崩
- [[E-12]]　上游配额或并发限制
    - 触发：OpenAI 配额 429、Kimi 并发 403、账号 reset window 未到
    - 期望：区分永久/窗口耗尽与瞬时错误，按 reset 冷却账号；保留其他账号故障转移
