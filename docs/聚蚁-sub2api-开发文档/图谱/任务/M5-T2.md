# M5-T2　维护上游转换、流式转发与 failover

- 所属模块：[[M5]]　协议网关与上游适配：入站路由、协议转换、能力门控、HTTP/WS/SSE 转发、failover 与取消传播
- 前置依赖：[[M4-T2]]、[[M5-T1]]
- 完成后解锁：[[M7-T1]]、[[M8-T1]]、[[M9-T2]]、[[M13-T1]]、[[M15-T1]]

## 输入 / 产出

- **输入**：规范化请求与选定账号
- **产出**：HTTP/SSE/WS 上游响应

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 首字节前重试排除失败账号并有上限（[[E-14]]）
2) 流开始后不拼接第二上游（[[E-15]]）
3) cancellation 传播并释放槽位（[[E-16]]）

## 必须处理的边界

- [[E-14]]　首字节前的可重试上游失败
    - 触发：transport error、可重试 429/5xx，且响应流未开始
    - 期望：排除失败账号并在上限内重选；耗尽后返回单一明确错误
- [[E-15]]　流开始后上游中断
    - 触发：SSE/WS/stream 已向客户端写出后 read error
    - 期望：不切换账号、不拼接第二响应；按协议发终止事件或关闭连接并记录错误
- [[E-16]]　客户端取消或 deadline 到期
    - 触发：HTTP context cancel、WS 断开、等待队列超时
    - 期望：向上游和槽位等待传播取消，及时释放并发资源，不继续计费无效工作

## 实施沉淀

<!-- notes:begin -->
首字节前失败可以换账号，因为客户端尚未观察响应；一旦写出 headers/event，重试会把两个协议流拼在一起并可能重复扣费。所有上游请求、等待计划和读循环都应使用请求 context，客户端取消后由同一所有权链释放槽位。
<!-- notes:end -->
