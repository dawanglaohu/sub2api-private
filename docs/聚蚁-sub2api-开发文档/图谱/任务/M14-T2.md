# M14-T2　维护兑换、优惠、分销与用户扩展权益

- 所属模块：[[M14]]　站点运营与管理能力：公共设置/模型广场、公告、渠道/代理、兑换/优惠/分销、备份/数据管理和管理 CLI
- 前置依赖：[[M3-T1]]、[[M6-T1]]、[[M14-T1]]
- 完成后解锁：[[M11-T1]]、[[M11-T2]]

## 输入 / 产出

- **输入**：redeem/promo/affiliate 请求、用户属性与余额/订阅
- **产出**：一次性核销、返利转移、公告投放和扩展属性记录

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 并发重放只结算一次并返回可追踪结果（[[E-39]]）
2) 余额/订阅/返利更新保持事务与审计
3) 管理批量操作和用户自助口径一致

## 必须处理的边界

- [[E-39]]　兑换码、优惠码或分销额度被并发重放
    - 触发：同一码/幂等键重复提交、两请求并发核销、转账与余额更新竞争
    - 期望：由唯一约束、幂等记录和事务只结算一次；冲突返回既有结果或明确失败并保留审计

## 实施沉淀

<!-- notes:begin -->
兑换、优惠和分销都把一次性凭据转换成余额、订阅或返利权益，正确性必须由数据库唯一约束、幂等记录和事务共同保证；应用层预检查只能提供友好提示。公告与用户属性虽不直接扣费，也会影响目标用户和运营决策，批量更新应保留审计并让用户端与管理端使用同一事实口径。
<!-- notes:end -->
