# M11-T2　维护管理员控制台与高风险操作

- 所属模块：[[M11]]　用户与管理控制台：用户 Keys/Usage/Payment/Profile 和管理员 Accounts/Groups/Ops/Settings/Plugins
- 前置依赖：[[M10-T2]]、[[M4-T1]]、[[M6-T2]]、[[M8-T1]]、[[M9-T2]]、[[M14-T1]]、[[M14-T2]]、[[M14-T3]]
- 完成后解锁：[[M12-T1]]、[[M12-T2]]

## 输入 / 产出

- **输入**：管理 API、设置、运营和 Ops 数据
- **产出**：Accounts/Groups/Settings/Ops/Plugins/运营管理面

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 高风险操作经过 audit + compliance/step-up（[[E-30]]）
2) 批量操作错误可定位且不半提交
3) 凭据和审计 payload 默认脱敏

## 必须处理的边界

- [[E-30]]　管理员高风险操作缺少再验证
    - 触发：修改支付/安全/身份设置，或 compliance 未确认
    - 期望：admin auth 之外继续执行 audit、compliance/step-up；失败时不落部分配置

## 代码位置

<!-- code:begin -->
- `frontend/src/views/admin/` — 账号、分组、设置、Ops、支付和插件页面
- `frontend/src/api/admin/` — 管理 API client
- `frontend/src/stores/adminCompliance.ts` — compliance 确认状态（E-30）
- `frontend/src/components/auth/TotpStepUpDialog.vue` — 管理员 step-up UI
- `backend/internal/server/routes/admin.go` — admin/audit/compliance/step-up 路由组合
<!-- code:end -->

## 实施沉淀

<!-- notes:begin -->
高风险管理动作的按钮可见性不是授权，后端仍按 route 组合执行 admin、audit、compliance 和 step-up。批量操作应返回可定位结果并保持事务边界；前端不能在部分失败时给出全量成功提示。
