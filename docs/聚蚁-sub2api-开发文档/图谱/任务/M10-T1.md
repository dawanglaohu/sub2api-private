# M10-T1　维护前端 API client、stores 与设置缓存

- 所属模块：[[M10]]　前端应用壳：API client、token refresh、Pinia stores、Router guards、layout、设置注入与懒加载
- 前置依赖：[[M1-T2]]、[[M3-T1]]
- 完成后解锁：[[M10-T2]]

## 输入 / 产出

- **输入**：REST 响应、JWT、public settings
- **产出**：单飞 refresh、Pinia 状态与错误模型

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 并发 401 只触发一次 refresh 并正确重放（[[E-27]]）
2) settings 失败保持 unknown 而非 false
3) logout 清理敏感本地状态

## 必须处理的边界

- [[E-27]]　公共设置或 token refresh 瞬时失败
    - 触发：首次导航、网络抖动、401 并发刷新
    - 期望：设置未知不等于功能关闭；refresh 单飞并正确重放/登出，避免重定向循环

## 代码位置

<!-- code:begin -->
- `frontend/src/api/client.ts` — request/response interceptor 与统一错误
- `frontend/src/api/tokenRefresh.ts` — refresh singleflight（E-27）

- `frontend/src/stores/app.ts` — public settings 缓存与 mode
- `frontend/src/stores/adminSettings.ts` — 管理设置投影

## 实施沉淀

<!-- notes:begin -->
设置请求失败保持 unknown，只有成功加载后的显式 false 才关闭功能。Refresh 由共享 promise 协调并发 401；失败后统一清理 session，单个请求不能各自刷新或反复把用户送回受保护路由。
