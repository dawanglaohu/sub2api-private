# M6-T2　维护支付订单、履约与退款

- 所属模块：[[M6]]　用量、订阅与支付：UsageLog、余额/订阅窗口、计价、订单、provider webhook、履约和退款
- 前置依赖：[[M6-T1]]
- 完成后解锁：[[M7-T2]]、[[M11-T2]]

## 输入 / 产出

- **输入**：订单、provider 回调、退款请求
- **产出**：余额/订阅履约与 PaymentAuditLog

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) webhook 先验签并幂等处理重复/迟到通知（[[E-18]]）
2) 本地和 provider 退款分裂有补偿与审计（[[E-19]]）
3) 状态转换使用事务 guard

## 必须处理的边界

- [[E-18]]　支付通知伪造、重复、乱序或迟到
    - 触发：webhook 签名错误，同一 trade 重放，取消/过期后收到真实付款
    - 期望：先验签再幂等状态转换；有效迟到付款可恢复履约，重复通知只返回已处理
- [[E-19]]　退款远端与本地状态分裂
    - 触发：本地权益已扣减但 provider 失败，或 provider 成功而本地提交失败
    - 期望：事务/补偿回滚并写审计；无法自动一致时进入 pending/failed，禁止伪装成功

## 代码位置

<!-- code:begin -->
- `backend/internal/server/routes/payment.go` — 用户、public、webhook 和 admin 路由
- `backend/internal/service/payment_order_lifecycle.go` — 取消、过期和查询状态 guard
- `backend/internal/service/payment_fulfillment.go` — PAID→RECHARGING→COMPLETED 履约（E-18）
- `backend/internal/service/payment_refund.go` — 退款扣减、provider 调用和补偿（E-19）
- `backend/internal/payment/provider/` — provider 验签、查询和退款 adapters
<!-- code:end -->

## 实施沉淀

<!-- notes:begin -->
Webhook 的真实性由 provider 验签决定，幂等性由订单状态 guard 和交易号约束决定，两者缺一不可。退款先锁定/扣减本地权益再调用远端时必须保留补偿路径；补偿失败写审计并停在可人工处理状态。
<!-- notes:end -->
