# 19 风险与技术债

## 高风险

| 风险 | 现状 | 缓解 |
|---|---|---|
| `service/` 规模过大 | 单层 1174 个 Go 文件，虽按前缀分域但发现成本高 | 通过模块/任务图谱导航；新代码继续按稳定前缀和窄文件职责拆分 |
| 前向迁移影响回滚 | 镜像 rollback 不等于数据 rollback | 发布前备份；跨大版本先审迁移；必要时恢复数据库 |
| 调度依赖 Redis 与 DB | cache/outbox lag 可能导致候选不全或 DB 雪崩 | 受限 fallback、QPS/timeout、lag rebuild 与 Ops 告警 |
| 流式协议失败复杂 | 首字节前/后重试语义完全不同 | 统一 stream-started 标记；流开始后绝不跨账号拼接 |
| 计费一致性 | usage、余额/订阅、异步任务和 provider webhook 跨事务边界 | mandatory record、幂等键、状态 guard、补偿和审计 |
| 插件进程扩大攻击面 | 上传包、独立进程、UI bridge、出站 OAuth | manifest/hash/path/size 校验、加密配置、健康检查、unavailable route |

## 聚蚁维护风险

- 二开净差异依赖“51 文件”审计口径；上游新增品牌附近功能时不能机械取 ours。
- `HomeView` 壳化会跳过上游官方首页新增内容；这是有意设计，但每次 release 应确认没有安全逻辑被放在官方页面而非共享层。
- `GroupBadge` 统一主题色会忽略上游新增平台配色；平台身份仍应通过 PlatformBadge/Icon 保留。
- `allowSelfUpdate=false` 是单点保护；上游若重构 VersionBadge，必须在 build/test 中重新搜索执行入口。
- `ext:` 是私有协议，后端 validation 和前端 rendering 必须同时保留。

## 文档风险

- 根目录历史记忆可能落后于 Git；知识库必须区分代码基线、生产镜像和回滚位。
- 受保护块若删除 marker，会在重跑时丢失；不要编辑派生正文。
- 行号会漂移，只给关键范围标行；模块根文件无需强行写行号。
- 每次任务落地前回写代码位置与实施沉淀，之后立即重跑和 `--check`。

## 暂不解决

- 不把单体强拆成微服务；当前优先保证协议/计费一致性和可发布性。
- 不为知识库引入 Dataview 等必需插件；纯 Obsidian wikilink/Graph View 即可使用。
- 不把生产凭据和实时数据复制进 vault。
