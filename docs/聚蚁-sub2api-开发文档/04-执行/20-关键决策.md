# 20 关键决策

| 决策 | 原因 | 后果 |
|---|---|---|
| `custom` 是唯一二开主分支，`upstream` 只读 | 保持上游历史可追踪，避免误推 | 所有 release 用 merge commit 合入，不用 cherry-pick 抹掉祖先关系 |
| 正式更新只认 release tag | `main` 可能包含未发布或 VERSION 同步提交 | CI 与人工更新都验证最新 `v*` tag 的可达性 |
| 版本优先由 `git describe` 获取 | 上游曾先打 tag 后补 VERSION，tag 树中文件会滞后一版 | CI 必须在 tag 可达后构建，推送顺序 tag→branch |
| 聚蚁能力优先新文件 | 降低上游合并冲突和语义覆盖 | 51 文件净差异可持续审计；少数插入点需定向测试 |
| 前端不加聚蚁专用依赖 | lockfile 是上游高冲突面 | 字体/视觉资产 vendored，动效使用原生 Canvas/CSS |
| `home_content` 优先于 JuyiHome | 保留管理员自定义首页能力 | 品牌首页是默认值，不是不可覆盖的硬编码 |
| `ext:` 由前后端共同实现 | 内嵌自定义页无法满足外部购卡站新窗口需求 | 后端只允许绝对 HTTP(S)，前端隔离 opener |
| 管理台自更新永久禁用 | 官方二进制/镜像会覆盖聚蚁 UI | VersionBadge 只读检查；更新走私有 GHCR SOP |
| Authentication 与 Billing Enforcement 分层 | 额度耗尽后仍需查 usage/billing/task | skipBilling 不能跳过 Key、用户、组、ACL 校验 |
| 流开始后禁止 failover | 两个上游流拼接会破坏协议和计费 | 仅首字节前重试；流后错误按当前协议终止 |
| PostgreSQL 是事实源，Redis 可重建 | 缓存/队列故障不能覆写余额、订单和身份事实 | fallback 必须受限，outbox lag 触发重建和告警 |
| 插件状态异常时 fail unavailable | 静默回落可能绕过管理员启用的安全/出站策略 | 权威状态读失败或 runtime 不健康时禁止不受控直连 |
| 生产只用 `custom-<sha8>` | 版本别名和 latest 会移动 | 可精确回滚和对账 manifest；发布前仍需数据库备份 |
| Smoke 与生产数据完全隔离 | 新二进制启动会执行迁移，误连生产不可接受 | 临时 PG/Redis；通过后另做生产备份再 switch |
| 整仓覆盖用主要模块归属而非逐文件笔记 | 数千文件逐篇复制会迅速腐烂，但外围目录又不能静默遗漏 | 第 21 节给出矩阵，`check_coverage.py` 对每个 tracked file 强制归属；跨模块语义仍由任务和边界表达 |
